## The task in one paragraph
An agent on a 40x40 grid city starts at a depot and must deliver 5 parcels. Terrain has costs, some cells are blocked, moves slip with probability 0.25, the agent has limited fuel (recharges at stations and the depot), there are teleport tunnels, the city has hills (our third twist), and a rival "blocker" agent (search depth 6) tries to get in the way. We implement search planners (Part B), adversarial search vs the rival (Part C), an LLM dispatcher that calls our planners as tools (Part D), and a UI with reproducible experiments and an IEEE report (Parts A/E). The full brief is in `docs/OEL_brief.txt`.

## Our instance (DO NOT regenerate or edit files in `data/`)
- instance_id: **38bfda97** (from `python scripts/oel_instance.py 505099 506676 534732 534733`)

### Twist 1+2 layout (`data/twists_38bfda97.json`, from `scripts/make_twists.py`, seeded from instance_id)
- charging stations: (23,11), (0,25), (21,28), (31,20); the depot (5,4) also recharges
- fuel capacity 98; base fuel burned per move into terrain: road 1, grass 1, mud 2, ford 3
- tunnels (bidirectional): (26,14)↔(22,35), (10,36)↔(4,2), (19,6)↔(38,12); a jump costs 2 and burns 1 fuel; elevation is ignored for tunnel jumps
- reference (brute-force UCS, **hills OFF**): optimal cost **307**, 2 recharges, ~1.85M nodes. No tunnels: 400. No fuel limit: 296. Use these as sanity checks with `--no-hills`.
- reference (stand-in UCS, **hills ON** with UP_COST=2, UP_FUEL=3, REGEN=1, all twists ON, fuel reserve 0): optimal cost **329** (+7.2% over 307), 2 recharges, 2 tunnel jumps, 135 moves, ~1.78M nodes. Same route as hills OFF (the fuel/station constraints pin it); with `--no-fuel` the hills DO change the route (296 -> 320, 41 different cells). The reference optima are always computed with `--fuel-reserve 0`.

### Twist 3 (ours): Hills with regenerative braking. Config flag `hills` (default ON once approved)
- `data/elevation_38bfda97.npy`: integer heights 0–9 per cell, generated by `scripts/make_elevation.py` (smooth: a sum of a few Gaussian "hills" seeded from instance_id, then rounded). Built in Turn 1.
- Let `dh = h(next) - h(current)` for a normal move.
- **Path cost:** `terrain_cost(next) + UP_COST * max(dh, 0)` with `UP_COST = 2`. Climbing is slower; descending costs no extra.
- **Fuel:** `fuel_burn(next) + UP_FUEL * max(dh, 0) - REGEN * max(-dh, 0)` with `UP_FUEL = 3`, `REGEN = 1`. Going downhill can RECOVER fuel; fuel is capped at capacity.
- **Invariant: `REGEN < UP_FUEL`.** Going up then back down always loses fuel net, so there is no "free fuel" loop and the fuel dimension stays well-founded. Keep this true if values are tuned, and explain it in the viva.
- **Consequences (viva points):** moves are direction-dependent (A→B ≠ B→A), so distance fields used by heuristics must be computed **backwards over reversed edges** from each stop; and fuel can increase without a station, so fuel-feasibility checks cannot assume fuel only goes down.
- The constants live in `oel/config.py`; never hard-code them.

## Shared interfaces (don't change signatures without recording it in HANDOFF.md)
```python
# State is a hashable tuple: (row, col, delivered_mask, fuel)
#   delivered_mask: int bitmask over the 5 stops (bit i = stop i delivered); goal = all bits set
#   (elevation is a property of the cell, so it does NOT need to be in the state)
class DeliveryProblem:
    def initial_state(self) -> tuple
    def is_goal(self, state) -> bool
    def actions(self, state) -> list[str]          # subset of "N","S","E","W","TUNNEL"
    def result(self, state, action) -> tuple       # deterministic transition (planning model)
    def step_cost(self, state, action, next_state) -> float
# Inside result(): entering a stop marks it delivered; entering a station or the depot refuels
# to capacity; hills adjust fuel (with regen, capped at capacity); a move is illegal if fuel
# would go below 0.

@dataclass
class SearchResult:
    path: list            # states, start..goal (empty if failed)
    actions: list
    cost: float
    nodes_expanded: int
    max_frontier: int
    runtime_s: float
    peak_mem_kb: float    # measured with tracemalloc
    solved: bool
    expanded_order: list | None = None   # OPTIONAL: cell (row, col) of each expanded state, in order,
                                          # capped at EXPANDED_ORDER_CAP (200k); drives the UI search animation
    stats: dict = {}      # OPTIONAL planner facts: reason (failure/cutoff/node_limit/time_limit/max_depth/
                          # memory_limit), goal_test, steps, IDS iterations + re_expansions, A* reopened,
                          # weight, stored_states (A*/UCS/IDA*: states held in memory)
```
- `ucs` / `astar` accept `max_states=` (memory cap -> reason `"memory_limit"`); `ida_star` (informed.py) is registered.
- **Default planner:** `oel.search.registry.default_planner` = A* + h_ours + fuel pruning (registered as `"astar_pruned"`). Used by the simulator's full replans, the run_all demo, the fuel-reserve experiment and the UI. The rejoin search stays UCS (its goal is not "deliver everything", so h_ours is not a valid heuristic for it).
- **Experiment framework:** `oel/experiments/framework.py`: `make_scenarios(n)` (30 seeded stop layouts on our map), `run_experiment(variants, n)` -> tidy DataFrame (parallel, cached in `oel/experiments/cache/`), `summarise()` -> mean + 95% bootstrap CI. Bump `FRAMEWORK_VERSION` if planner results change.
### Game interface (Part C; defined in Turn 2, used as is by Turn 3)
```python
# oel/game/state.py
@dataclass(frozen=True)            # hashable: usable as a transposition-table key
class GameState:
    agent: tuple                   # our cell (row, col), FULL-map coordinates
    rival: tuple | None            # the rival's cell
    delivered_mask: int
    fuel: int
    step: int                      # OUR moves so far (a turn = our move, then the rival's)
    target_stop: int | None        # the stop our A* plan delivers next
    path: tuple                    # the next PATH_LEN (8) cells of our plan
    to_move: str = "agent"         # "agent" | "rival"
    ctx: GameContext               # map facts (problem, world, distance fields); NOT part of == / hash
    agent_state -> (row, col, mask, fuel)   # property, for problem.actions()/result()

GameContext.for_problem(problem) -> GameContext      # cached per map
from_simulator(sim, plan_states=None) -> GameState   # reads sim.plan_states / sim.plan_index
make_state(ctx, agent, rival, delivered_mask=0, fuel=None, ...) -> GameState
is_terminal(state) -> (bool, "win" | "loss" | "draw" | "running")
after_agent_move(state, new_agent_state) -> GameState   # bookkeeping only; legality = caller
after_rival_move(state, new_rival_cell) -> GameState
agent_moves(state) -> list[str]                      # real-world legal moves minus the rival's cell

# oel/game/evaluation.py
features(state) -> dict            # progress, delivered, interference, race, mobility, fuel_safety
evaluate(state, weights=None) -> float   # OUR point of view; +-1000 (win/loss), 0 (draw)
DEFAULT_WEIGHTS                    # {feature: weight}

# oel/game/tuning.py   (play_fn(weights, seed) -> "win"|"draw"|"loss", a TOP-LEVEL function)
grid_search(play_fn, weight_grid, n_games, seed) -> DataFrame
coordinate_ascent(play_fn, start_weights, steps, n_games, seed) -> (best_weights, DataFrame)
plot_weight_heatmap(df, x, y, name)
```
Terminal rules match the simulator: win = all delivered; loss = no legal move even without the rival (stranded) or an unreachable stop; draw = `cfg.max_steps`. Boxed in ONLY by the rival is NOT terminal (the evaluation penalises it). The Simulator takes `on_step=callback(sim)` (called after every step) and exposes `sim.plan`, `sim.plan_states`, `sim.plan_index`.

Planners: `planner(problem, **kwargs) -> SearchResult`. Heuristics: `h(state, problem) -> float`.
Register them in `oel/search/registry.py` (`register_planner(name, fn, uses_heuristic=...)`, `register_heuristic(name, h)`); the UI, the LLM tools and the plan cache read the registries. `DeliveryProblem(config, constraints=PlanConstraints(...))` adds user constraints (`oel/world/constraints.py`); `verify_plan(actions, constraints, cfg)` checks a plan independently.
